# Agent 运维能力 · Plan

- 将 Run 状态、步骤、用量与审批快照放在同一 Trace 记录；以 runId 串行追加和转移，避免状态与工具进度跨文件不一致。编排器用本地 AbortController 管理活动运行；新增按 ID 的 SSE 订阅重放已提交步骤，发送状态与 done，不绑定提交连接。后台最多并行四个任务、保留 100 个队列位置；先预留位置再提交或领取审批。
- 扩展可替换的 TraceStore 和 VectorStore，参考文件存储实现持久化列表和索引操作。用检索结果附带的稳定切片引用构造 citations，通过答案标记匹配，来源由执行器从真实检索能力提取，不解析模型臆造的 JSON。
- CLI 复用 runAssertions，业务工程通过自己的 HTTP 服务及授权运行评测。顺序执行用例与轮次，分配独立线程，仅在报告中记录断言、状态、耗时与 runId。
- 审批快照保存消息、当前轮次、工具列表、已执行结果、待批能力和剩余预算，不序列化模型、工具实例或信号。图从 execute 恢复，保留已经提交的步骤。恢复时检查能力归属和当前权限；会话若发生变化，保留更新后的对话，避免用旧快照覆盖。
- 委派通过图的保留工具执行分支，复用现有 Agent 注册表和生产编排；限制共享预算并在步骤记录子 runId。
